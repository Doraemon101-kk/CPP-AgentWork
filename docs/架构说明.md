# 架构与阅读路线

## 完整数据流

```text
输入问题 / 命令
  ↓
Workbench：会话、配置、项目索引
  ↓                         ↑
模型HTTP请求 → 工具请求 → 工具执行结果
  ↓
修改提案 → 用户预览/应用 → CMake/CTest → 错误反馈或成功结果
  ↓
持久会话、事件日志、Markdown报告
```

## 按职责阅读

1. `src/main.cpp`：解析--workbench及参数，进入工作台。
2. `src/app/workbench.cpp`：交互命令、会话文件、工具执行、报告。
3. `src/app/conversation.cpp`：工具Schema、历史上下文、有界模型循环、工具参数校验。
4. `src/workspace/index.cpp`：文件扫描、词法函数/类型与TODO候选索引。
5. `src/workspace/edits.cpp`：提案→pending→applied→undone/discarded；精确匹配与冲突检查。
6. `src/runtime/process.cpp`：无shell参数传递、进程树、输出、超时、CTest结果。
7. `src/runtime/model.cpp`：WinHTTP资源释放、请求发送、状态检查、JSON解析。

## 一次修改的状态

propose_edit先读取当前原文，要求旧片段唯一匹配，保存before/after和预览；源码此时不变。apply再次比对磁盘内容与before，一致才原子替换。undo要求磁盘内容仍等于after，再恢复before。新文件的undo删除本次创建且未经后续改动的文件。跨文件修改逐项应用，任一冲突明确报告。

## 上下文与记录

完整当前工具消息成对保留；近期最多4轮完成问答和较早摘要按预算回带。确定性文件/检查事实与模型摘要分开，SHA-256变化使旧证据失效。超大工具输出压缩并标记截断。事件按行追加，同时在会话中保留最近150条；失败轮次写明failed。项目状态按规范化根路径隔离，原始事件日志保存于本机。

## C++阅读重点

路径和字符串的值/借用、容器排序、RAII句柄、异常与错误返回、类的职责、消息结构、文件原子替换、子进程生命周期。先沿真实任务读调用链，再查看平台接口细节。

## v0.2新增职责

- `src/runtime/task.cpp`：任务状态、Ctrl+C信号、跨实例取消请求。控制处理器只置原子标志，不在信号线程读写会话或关闭HTTP句柄。
- `src/runtime/model.cpp`：异步WinHTTP回调与完成事件；按可用字节接收NDJSON；文字增量显示，工具参数累积；取消时请求句柄关闭并等HANDLE_CLOSING后释放回调上下文。
- `src/app/context.cpp`：较早问答摘要、固定笔记、SHA-256事实、上下文预算；原始记录不被摘要替换。
- 工作台按ask/edit/check过滤Schema并在工具分发处再次检查。默认ask，显式编辑才允许提出修改。

取消边界：模型HTTP和检查进程可取消；文件原子替换与修改记录提交不提供中途取消接口。已应用修改保留，使用/undo显式撤销。
